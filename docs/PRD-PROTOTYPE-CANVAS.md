# PRD: 프로토타입 캔버스 편집 레이어

## 부모 PRD와의 관계

- **부모 문서**: [`docs/PRD.md`](./PRD.md) v0.2 (Draft, 2026-08-24)
- **부모 구현 Plan**: [`docs/IMPLEMENTATION-PLAN.md`](./IMPLEMENTATION-PLAN.md) v0.2
- **본 문서 역할**: 부모 워크플로의 **5단계(프로토타입)** 위에 얹는 **기능 확장 PRD**. 컨셉→팔레트→와이어프레임→컴포넌트 세트의 확정 규칙, 1차 범위(로그인 없음, `localStorage` 키 `protomatch:projects`, 인증·Supabase·크레딧 제외)는 부모를 그대로 상속한다.
- **하지 않는 것**: 부모 `docs/PRD.md`를 대체하거나 덮어쓰지 않는다. 단계 스킵 허용, 최종 화면을 1단계로 끌어올리기, 상용화 인증/원장을 본 기능에 끌어오지 않는다.

#### 1.1 한 줄 요약

앞 4단계가 확정된 프로토타입 화면 위에서, 확정 키트·팔레트 스타일의 컴포넌트 인스턴스를 왼쪽 팔레트에서 추가하고 자유롭게 옮기며, 오른쪽 인스펙터로 속성과 생성 코드를 보는 **로컬 전용 편집 레이어**다.

#### 1.2 용어 정의

| 용어 | 정의 |
| --- | --- |
| **베이스 목업** | 확정 컨셉·팔레트·와이어·컴포넌트 키트로 그리는 기존 라이브 HTML 화면 (`prototype-screen`). P0에서 선택·이동 불가인 배경 레이어. |
| **캔버스** | 베이스 목업 위에 인스턴스를 절대 좌표로 올리는 편집 표면. 프로토타입 프레임 내부 좌표계. |
| **팔레트(컴포넌트 팔레트)** | 왼쪽 사이드 메뉴의 **추가 가능한 컴포넌트 종류 목록**. 컬러 팔레트(단계 2 산출물)와 이름이 겹치므로 본 문서에서는 “컴포넌트 팔레트”로 구분한다. |
| **인스턴스** | 캔버스에 배치된 컴포넌트 1개. `id, type, x, y, width, height, props, zIndex`를 가진다. |
| **인스펙터** | 선택된 인스턴스의 속성을 조절하고, 읽기 전용 생성 코드를 보여 주는 오른쪽 패널. |
| **키트 스타일** | 확정 컴포넌트 세트의 `solid` / `soft` / `compact` 시각 규칙(모서리, 높이, 밀도). |
| **토큰 재바인딩** | 인스턴스 좌표·사용자 카피는 유지한 채, 확정 팔레트 hex와 키트 스타일만 다시 입히는 동작. |
| **편집 잠금** | 프로토타입 단계가 열리지 않거나 stale일 때 인스턴스 추가·이동·속성 변경을 막는 상태. 저장된 트리는 지우지 않는다. |

#### 1.3 기술 가정 (제품 관점, 구현 세부는 미확정)

- **가정**: 1차와 동일하게 브라우저만. 프로젝트 영속은 `localStorage` (`protomatch:projects`). 서버 동기화·계정 없음.
- **가정**: 기존 최종 화면(라이브 HTML 목업)을 **삭제하지 않고** 그 위에 오버레이한다. 생성 파이프라인·상태머신은 부모 PRD 규칙을 유지한다.
- API 계약, 드래그 라이브러리, 코드 생성 템플릿 문법은 본 PRD에서 확정하지 않는다. 필요 시 기술 스파이크.

### 2. 배경·문제 정의

#### 2.1 현재 상황

ProtoMatch는 분야+키워드 이후 컨셉→팔레트→와이어프레임→컴포넌트 세트를 한 단계씩 확정한 뒤에만 최종 프로토타입을 보여 준다. 최종 화면은 확정값을 반영한 **라이브 HTML 목업**이다. 사용자는 그 화면을 보고 합의할 수 있지만, **목업 위에 버튼을 하나 더 올리거나 카피를 바꿔 위치를 옮기는 편집**은 없다. 조정이 필요하면 앞 단계를 재생성하거나 외부 툴로 나간다.

#### 2.2 해결하려는 문제

1. **합의 직후 미세 조정 공백**: “이 버튼이 여기 있으면 좋겠다”를 프로토타입 단계에서 바로 시험할 수 없다.
2. **핸드오프 단절**: 개발자는 목업만 보고 컴포넌트 속성·마크업을 다시 추정한다. 선택된 블록의 **안전한 생성 코드**가 없다.
3. **단계 가치 훼손 위험**: 자유 캔버스를 너무 일찍 열면 컨셉·팔레트·와이어 확정이 우회된다. 따라서 편집은 **프로토타입 단계의 레이어**로만 연다.

#### 2.3 왜 지금인가

- 1차 워크플로와 라이브 목업이 이미 있다. 캔버스는 그 산출물 위에 얹는 것이 가장 싸다.
- 기획자·창업자가 Figma 없이 “한 화면을 만져 보는” 수요가 프로토타입 단계에 몰린다.
- 기회: 단계형 합의 + 가벼운 배치 편집. 리스크: Figma 대체로 범위가 커지면 1차 로컬 제품이 무거워진다. 비목표로 고정한다.

#### 2.4 Positioning (한 줄)

확정된 키트와 색으로만 그리는 **프로토타입 위 로컬 캔버스**. 실시간 협업 툴이 아니다.

### 3. 목표·비목표

#### 3.1 목표 (Goals)

1. 중간 4단계가 모두 `committed`이고 stale이 없는 프로젝트에서, 사용자는 프로토타입 단계 UI의 **왼쪽 컴포넌트 팔레트**를 보고 종류를 고를 수 있다.
2. 같은 조건에서 **적용 클릭** 또는 **팔레트→캔버스 드래그**로 인스턴스를 1개 이상 추가할 수 있다. 적용으로 추가한 인스턴스의 최초 위치는 프로토타입 화면 **정중앙**이다.
3. 배치된 인스턴스를 포인터로 **드래그해 임의 좌표로 옮길** 수 있다. 좌표는 캔버스 프레임 기준이며, 새로고침 후에도 같은 브라우저에서 유지된다.
4. 인스턴스를 **하나만 선택**하면 오른쪽 인스펙터에 **조절 가능한 속성**과 **읽기 전용 생성 코드**(복사 가능)가 보인다. 코드는 실행되지 않는다.
5. 인스턴스의 시각(모서리, 밀도, 역할색)은 **확정 팔레트 hex + 확정 키트(solid/soft/compact)** 를 따른다. 앞 단계 재확정 후 프로토타입이 다시 유효해지면 좌표·사용자 입력 텍스트는 유지하고 스타일만 갱신한다(섹션 6.4).

#### 3.2 비목표 (Non-goals) — 이번 기능에서 하지 않음

- 앞 4단계를 건너뛰고 빈 캔버스에서 시작하는 플로.
- **실시간 협업**, presence, 동시 편집, 충돌 해소.
- **Figma 파일 export**, 플러그인, Dev Mode 동기화, FigJam.
- **반응형 오토레이아웃 엔진**(컨스트레인트, 스택, 브레이크포인트별 자동 재배치). P0 좌표는 px 절대값.
- **커스텀 코드 실행**(`eval`, `new Function`, iframe 임의 스크립트, 사용자가 붙여 넣은 JS 실행).
- 컴포넌트 팔레트에 없는 타입을 코드로 등록하는 플러그인 시스템.
- 멀티 스크린·플로 연결, 핫스팟 프로토타이핑(화면 간 클릭 이동).
- 벡터 펜, 오토 애니, 프로토타이핑 인터랙션 타임라인.
- 인증, Supabase, 크레딧, 서버 영속 — 부모 1차와 동일하게 **상용화 범위**.
- 모바일 퍼스트 캔버스 제스처. **가정**: 데스크톱 포인터 우선. 터치 최소 동작은 P1 이후.

### 5. 사용자 스토리 / 시나리오

#### 5.1 사용자 스토리

1. **As a** 기획자, **I want** 프로토타입 단계에서 왼쪽 목록의 버튼을 적용하거나 캔버스로 드래그하고 싶다, **so that** 확정 목업을 깨지 않고 CTA를 시험할 수 있다.  
2. **As a** 창업자, **I want** 방금 적용한 컴포넌트가 화면 한가운데 생기고 이후 마우스로 옮기고 싶다, **so that** 좌표를 숫자로 맞추지 않아도 된다.  
3. **As a** 개발자, **I want** 선택한 인스턴스의 속성을 바꾸고 생성 코드를 복사하고 싶다, **so that** 핸드오프 때 색·라벨을 다시 추측하지 않는다.  
4. **As a** 사용자, **I want** 같은 브라우저에서 새로고침한 뒤에도 인스턴스 위치와 속성이 남아 있기를 원한다, **so that** 데모 직전에 작업이 사라지지 않는다.  
5. **As a** 사용자, **I want** 앞 단계에서 팔레트나 키트를 다시 확정해도 내가 놓은 블록이 좌표째 날아가지 않기를 원한다, **so that** 배치 작업을 재사용하고 색만 갱신된다.

#### 5.2 핵심 유저 플로 (프로토타입 단계)

```
[선행] 컨셉·팔레트·와이어·컴포넌트 세트 확정, stale 없음
  → 워크벤치 프로토타입 스텝
  → 중앙: 베이스 목업 + 캔버스 오버레이
  → 좌: 컴포넌트 팔레트 (종류 목록 + 항목별 적용)
  → (A) 적용 클릭 → 인스턴스 캔버스 정중앙에 생성, 자동 선택
  → (B) 팔레트 항목을 캔버스 위로 드래그 드롭 → 인스턴스 생성 (배치 규칙은 섹션 6.2)
  → 인스턴스 드래그로 재배치
  → 클릭 선택 → 우: 인스펙터 (속성 폼 + 읽기 전용 코드 + 복사)
  → 스토어가 프로젝트에 인스턴스 트리 저장 (localStorage)
```

stale이거나 4단계 미확정이면 이 플로의 편집 컨트롤은 열리지 않거나 잠긴다. 베이스 목업 조회 규칙은 부모 PRD(최종 잠금)를 따른다.

### 6. 기능 요구사항

우선순위: **P0** = 이번 기능 MVP(사용자 요청 핵심 + 편집 성립에 필수인 최소 동작). **P1** = 다음 스프린트. **P2** = 이후.

사용자 원문의 P0: 왼쪽 목록, DnD 추가, 적용 버튼, 중앙 배치, 자유 드래그 이동, 우측 속성+코드.  
아래는 그 위에 **단일 선택·영속·확정 스타일 반영·stale 정책**을 P0에 포함한다. 선택 없이는 인스펙터가 성립하지 않고, 저장 없이는 데모가 깨진다.

#### 6.0 게이트 (P0, 워크플로 보호)

캔버스 편집 레이어는 **프로토타입 단계가 생성·조회 가능한 상태**에서만 활성이다.

- 활성 조건: 컨셉·팔레트·와이어프레임·컴포넌트 세트가 각각 `committed`이고, 어느 것도 `stale`이 아님. (부모 `canGenerate(project, "prototype")`와 동일 가드.)
- 비활성 시: 컴포넌트 팔레트·드롭 존·인스펙터 편집은 숨기거나 disabled. 잠금 이유 문구(어느 단계가 비었는지/stale인지)를 보여 준다.
- 앞 4단계 UI·확정 버튼·생성 API 가드를 변경하지 않는다.

**수용 기준**

- Given 와이어프레임만 확정된 프로젝트에서, When 프로토타입 스텝을 열면, Then 컴포넌트 팔레트로 인스턴스를 추가할 수 없고 선행 확정 안내가 보인다.  
- Given 4단계가 확정된 뒤 컨셉을 재확정해 이후가 stale인 프로젝트에서, When 프로토타입 스텝을 열면, Then 기존 인스턴스 데이터는 스토어에 남아 있으나 추가·이동·속성 변경은 불가이고 stale 안내가 보인다.  
- Given 4단계가 다시 모두 committed이고 stale이 없으면, When 프로토타입 스텝을 열면, Then 팔레트·DnD·적용·드래그 이동·인스펙터가 활성이다.

#### 6.1 레이아웃: 3열 편집 셸 (P0)

프로토타입 스텝의 결과 영역은 다음을 한 화면에 배치한다.

| 영역 | 역할 |
| --- | --- |
| 좌측 | 컴포넌트 팔레트 (종류 목록, 항목별 적용) |
| 중앙 | 기존 프리뷰 프레임 안의 베이스 목업 + 캔버스 오버레이 |
| 우측 | 인스펙터. 선택 없으면 빈 상태 문구 |

베이스 목업은 P0에서 **클릭해도 선택되지 않는 배경**이다. 히트 테스트는 인스턴스와 팔레트·인스펙터 컨트롤만 받는다.

**수용 기준**

- Given 편집이 활성일 때, When 프로토타입 스텝을 보면, Then 좌측 목록·중앙 프레임·우측 패널이 동시에 보인다.  
- Given 베이스 목업의 버튼 영역을 클릭해도, When 그 아래 인스턴스가 없으면, Then 인스펙터는 빈 상태를 유지하고 목업 DOM을 드래그로 옮기지 않는다.

#### 6.2 컴포넌트 팔레트와 추가 (P0)

##### 6.2.1 팔레트에 넣을 종류 (제품 제안, 리뷰 후 확정)

확정 컴포넌트 세트의 역할과 1:1로 맞추고, 화면을 채우기 위한 **최소 확장**만 둔다.

| 타입 `type` | 출처 | 기본 역할 |
| --- | --- | --- |
| `button` | 키트 role | CTA |
| `input` | 키트 role | 한 줄 입력 |
| `card` | 키트 role | 제목+본문 블록 |
| `navigation` | 키트 role | 가로 내비/레일 조각 |
| `badge` | 키트 role | 상태·태그 |
| `tabs` | 키트 role | 탭 스트립 |
| `heading` | 최소 확장 | 제목 텍스트 |
| `text` | 최소 확장 | 본문 텍스트 |
| `image` | 최소 확장 | 이미지 플레이스홀더(외부 URL 또는 빈 면). **가정**: P0는 업로드 없이 placeholder / 공개 URL 문자열만 |

키트에 해당 role 아이템이 있으면 팔레트 항목 부제에 확정 세트의 `variant` 힌트를 보여 줄 수 있다. role이 세트에 없어도 위 9종은 P0 팔레트에 **항상** 둔다(와이어와 무관하게 한 화면을 만질 수 있게). 시각은 그래도 확정 키트·팔레트를 쓴다.

P0에 넣지 않음: 아이콘 세트, 테이블, 차트, 모달, 드롭다운 메뉴 전체, 커스텀 HTML.

##### 6.2.2 적용 버튼

각 팔레트 행은 **적용** CTA를 가진다. 클릭 시 해당 `type` 인스턴스 1개를 생성한다.

- 최초 `x, y`: 인스턴스 **박스의 중심**이 캔버스(프로토타입 화면)의 중심과 일치.  
- 최초 `width, height`: 타입별 기본값(섹션 6.2.4).  
- 최초 `zIndex`: 현재 트리 최댓값 + 1 (없으면 1).  
- 최초 `props`: 타입 기본값 + 확정 키트/팔레트에서 파생한 읽기 전용 토큰(사용자가 색 hex를 임의 입력하지는 P0에서 금지, **역할 토큰**만).  
- 생성 직후 그 인스턴스를 **단일 선택**한다.

**수용 기준**

- Given 편집이 활성이고 캔버스 크기가 W×H일 때, When 사용자가 `button`의 적용을 누르면, Then `type=button` 인스턴스가 1개 생기고 박스 중심 좌표가 `(W/2, H/2)`이며 인스펙터에 해당 인스턴스가 열린다.  
- Given 이미 인스턴스가 있을 때, When 적용을 다시 누르면, Then 새 인스턴스가 추가되고 이전 인스턴스는 좌표를 유지한다. 새 인스턴스가 선택된다.

##### 6.2.3 드래그 앤 드롭으로 추가

팔레트 항목을 중앙 캔버스 위로 드래그해 놓을 수 있다.

- **P0 확정 제안**: 드롭이 캔버스 **내부**에서 끝나면 인스턴스를 생성한다.  
- **가정 (드롭 좌표 vs 중앙)**: 사용자 원문은 “놓기”와 “기본 위치 정중앙”을 함께 말한다. P0 기본값은 **적용=중앙**, **DnD=드롭 지점이 인스턴스 중심**(캔버스 밖으로 나가면 클램프). 드롭이 캔버스가 아닌 곳에서 끝나면 생성하지 않는다.  
- 오픈 이슈 1에서 DnD도 무조건 중앙으로 바꿀 수 있다.

**수용 기준**

- Given 편집이 활성일 때, When 사용자가 `card`를 캔버스 안쪽으로 드롭하면, Then `type=card` 인스턴스가 1개 생기고 선택된다.  
- Given 드래그가 캔버스 밖에서 끝나면, When 드롭하면, Then 인스턴스는 생기지 않는다.  
- Given 편집이 잠금일 때, When 팔레트에서 드래그하면, Then 드롭으로 인스턴스가 생기지 않는다.

##### 6.2.4 타입별 기본 박스 (P0 가정, px)

캔버스 논리 크기 **가정**: 베이스 목업과 동일한 프레임. 구현이 스케일(CSS transform)을 쓰면 **논리 좌표**를 저장하고 화면 스케일과 분리한다(오픈 이슈 5).

| type | width | height |
| --- | --- | --- |
| button | 136 | solid/soft 40, compact 28 |
| input | 240 | solid/soft 40, compact 28 |
| card | 280 | 176 |
| navigation | min(캔버스 너비-48, 640) | 48 (compact 40) |
| badge | 88 | 24 |
| tabs | 320 | 40 |
| heading | 320 | 48 |
| text | 280 | 72 |
| image | 240 | 160 |

#### 6.3 재배치 (P0)

이미 놓인 인스턴스는 포인터 드래그로 옮긴다. Figma형 **자유 좌표**다. 오토레이아웃 없음.

- 드래그 중 인스턴스는 포인터 이동량을 따른다.  
- 박스가 캔버스 밖으로 완전히 사라지지 않도록 **가정**: 최소 16px가 프레임 안에 남게 클램프.  
- P0에 스냅·가이드 없음. 이동은 1px 단위.  
- 이동 종료 시 스토어에 `x, y`를 쓴다.

**수용 기준**

- Given 선택된 인스턴스가 있을 때, When 사용자가 그 인스턴스를 드래그해 버튼을 떼면, Then `x, y`가 드롭 시점에 맞고 인스펙터 좌표 표시(있다면)와 일치한다.  
- Given 인스턴스를 프레임 모서리 밖으로 강하게 드래그하면, When 버튼을 떼면, Then 인스턴스 전체가 화면에서 소실되지 않고 클램프된 좌표에 있다.  
- Given 베이스 목업만 드래그하면, When 포인터를 움직여도, Then 인스턴스 좌표는 변하지 않는다.

#### 6.4 앞 단계 재확정(stale) 시 캔버스 정책 (P0)

부모 섹션 6.4(재생성 시 이후 stale, 최종 잠금)를 캔버스에 연장한다.

| 상황 | 인스턴스 트리 | 편집 | 시각 |
| --- | --- | --- | --- |
| 이후 단계 stale / 프로토타입 가드 실패 | **유지** (삭제하지 않음) | **잠금** | 마지막 렌더 유지 가능. 배너로 잠금 이유 |
| 사용자가 이후 단계를 다시 확정해 가드 통과 | **유지** | **잠금 해제** | **토큰 재바인딩**: hex·키트 반경·키트 밀도만 갱신. `x,y,width,height`, 사용자 `props`(라벨, placeholder 등) 유지 |
| 프로토타입 “다시 생성”(베이스 목업 재생성) | **유지** | 가드가 통과 중이면 편집 유지 | 베이스 목업만 갱신. 오버레이 인스턴스는 그대로 |
| 브리프 변경으로 전 단계 stale | **유지** | **잠금** | 동일 |
| 사용자가 **캔버스 비우기** 실행 | 빈 배열 | 활성일 때만 | 베이스 목업만 남음 |

**하지 않음 (P0)**

- stale 발생 시 트리 자동 초기화.  
- stale 중에도 좌표 편집 허용.  
- 키트 role이 바뀌었다고 타입을 자동 삭제.

키트 불일치(예: 세트 설명과 무관)는 경고 배지 정도만 P1. P0는 9종을 항상 렌더한다.

**수용 기준**

- Given 인스턴스 2개가 있는 프로젝트에서 컨셉을 재확정하면, When 스토어를 보면, Then 인스턴스 `id`와 `x,y`는 그대로이고 프로토타입 편집은 잠긴다.  
- Given 그 상태에서 팔레트·키트까지 다시 확정하면, When 편집이 다시 열리면, Then 같은 2개가 보이고 색·모서리는 **새** 확정 팔레트·키트를 따르며 라벨 문자열은 이전과 같다.  
- Given 사용자가 캔버스 비우기를 확인하면, When 완료되면, Then 인스턴스 수는 0이고 베이스 목업은 남는다.  
- Given stale 잠금에서 캔버스 비우기를 누르면, When 클릭하면, Then 트리는 변하지 않거나 컨트롤이 disabled다. (**가정**: 비우기는 편집 활성일 때만)

#### 6.5 선택과 인스펙터 (P0)

##### 6.5.1 단일 선택

- 인스턴스 클릭 → 그 인스턴스만 선택. 선택 링(색+두께, 색만으로 구분 금지).  
- 캔버스 빈 곳(인스턴스 밖, 베이스는 무시) 클릭 → 선택 해제.  
- 다중 선택은 P1.  
- **가정**: 새로고침 후 선택은 비움. 트리는 복원.

**수용 기준**

- Given 인스턴스 A, B가 있을 때, When A를 클릭하면, Then A만 선택되고 인스펙터는 A의 속성과 코드를 보여 준다.  
- Given A가 선택된 때, When 캔버스 빈 곳을 클릭하면, Then 선택이 없고 인스펙터는 빈 상태다.

##### 6.5.2 속성 편집 (안전)

인스펙터는 **스키마에 있는 필드만** 폼으로 수정한다. 자유 텍스트를 코드로 평가하지 않는다.

공통 필드(P0): `x`, `y`, `width`, `height`(숫자, 최소 크기 타입별 하한). 숫자 변경은 캔버스와 즉시 동기화.

타입별 `props` 예(제품 수준, 필드명은 구현 시 고정):

| type | P0 편집 속성 |
| --- | --- |
| button | label, 색 역할(`primary`/`accent` 등 스와치 role), disabled(boolean) |
| input | label, placeholder, value(목업 문자열) |
| card | title, body |
| navigation | 항목 텍스트 2~5개(단순 리스트) |
| badge | label, 색 역할 |
| tabs | 탭 라벨 2~4개, 활성 인덱스 |
| heading | text, 수준(h1~h3) |
| text | text |
| image | alt, src(URL 문자열, 빈 값이면 placeholder 면) |

색은 **확정 팔레트의 role**만 고른다. 임의 hex 피커는 P1.

**수용 기준**

- Given 버튼이 선택된 때, When 라벨을 “가입”으로 바꾸면, Then 캔버스 버튼 문구가 “가입”이 되고 저장된다.  
- Given 인스펙터에 JS를 속성으로 붙여 넣어도, When 저장되면, Then 문자열로만 렌더되고 스크립트는 실행되지 않는다.  
- Given width를 하한 미만으로 입력하면, When 블러/제출하면, Then 하한으로 클램프되고 캔버스가 0 크기가 되지 않는다.

##### 6.5.3 코드 패널 (읽기 / 복사)

- 선택 인스턴스에 대한 **생성 마크업**을 읽기 전용으로 보여 준다.  
- **복사** 버튼으로 클립보드에 넣는다.  
- 사용자가 코드 패널을 편집해도 캔버스에 반영하지 않는다. (편집 가능 textarea로 보여 줄 경우에도 apply 없음.)  
- **가정**: 언어는 JSX(React) 한 블록. hex는 인라인 또는 CSS 변수 주석. 키트 반경이 반영된다. HTML-only는 오픈 이슈 4.

**수용 기준**

- Given 버튼 라벨과 accent 역할이 설정된 때, When 코드 패널을 보면, Then 라벨 문자열과 확정 accent hex(또는 role 토큰)가 텍스트에 포함된다.  
- Given 복사 클릭 후, When 클립보드를 읽으면(테스트/수동), Then 패널에 보이던 텍스트와 같다.  
- Given 코드 패널 문구를 사용자가 고쳐 써도, When 캔버스를 보면, Then 인스턴스 시각은 인스펙터 **폼 값**만 따른다.

#### 6.6 영속 (P0)

인스턴스 트리를 프로젝트 객체에 넣고 기존 persist로 저장한다.

개념 필드(테이블/SQL 아님):

```
CanvasInstance {
  id: string
  type: CanvasComponentType
  x: number
  y: number
  width: number
  height: number
  props: object  // 타입별, JSON-직렬화 가능, 함수/HTMLNode 금지
  zIndex: number
}
```

프로젝트에 `canvasInstances: CanvasInstance[]` (이름 가정). `updatedAt` 갱신.

- 조회·목록·다른 스텝 이동 후 복귀해도 동일 트리.  
- 시크릿 모드·다른 브라우저·쿼터 초과는 부모와 동일하게 보장하지 않음.

**수용 기준**

- Given 인스턴스 3개를 배치·속성 수정한 뒤, When 페이지를 새로고침하고 같은 프로젝트를 열면, Then `id, type, x, y, width, height, props, zIndex`가 동일하다.  
- Given `protomatch:projects`를 지운 때, When 앱을 열면, Then 프로젝트와 캔버스가 함께 없다.

#### 6.7 삭제 (P0 Must — 원문 목록 외 추가)

적용만 있고 삭제가 없으면 캔버스가 복구 불가하게 오염된다. **선택된 인스턴스 1개 삭제**를 P0 Must로 둔다.

- 인스펙터 **삭제** 버튼.  
- 키보드 Delete / Backspace는 포커스가 입력 필드가 아닐 때.  
- 삭제 후 선택 없음. Undo는 P1이므로 확인 다이얼로그는 **가정**: P0는 확인 없이 즉시 삭제(오픈 이슈 6에서 확인 추가 가능).

**수용 기준**

- Given 인스턴스 A가 선택된 때, When 삭제를 실행하면, Then A가 트리에서 사라지고 캔버스·스토어·인스펙터 빈 상태가 일치한다.  
- Given 선택이 없을 때, When Delete 키를 누르면, Then 아무 인스턴스도 지우지 않는다.

#### 6.8 P1 — Should

각 항목 수용 기준 포함.

##### P1-1. 다중 선택

Shift/드래그 박스 또는 Shift+클릭으로 여러 인스턴스. 함께 이동. 인스펙터는 “n개 선택” 또는 공통 속성만.

**수용 기준**: Given A, B를 다중 선택한 때, When 드래그하면, Then A와 B의 상대 간격이 유지된 채 이동한다.

##### P1-2. 되돌리기 / 다시 실행

추가·삭제·이동·속성 변경에 대한 Undo/Redo. 단축키 표준(⌘Z / ⌘⇧Z). 히스토리 스택은 세션 메모리. **가정**: 새로고침 시 언두 스택은 비움, 트리는 persist.

**수용 기준**: Given 방금 인스턴스를 추가한 때, When Undo하면, Then 그 인스턴스가 제거되고 Redo로 복구된다.

##### P1-3. z-index 조절

인스펙터 또는 컨텍스트: 앞으로 / 뒤로 / 맨 앞 / 맨 뒤. P0는 생성 순서 = 위만.

**수용 기준**: Given A가 B 아래 있을 때, When A에 맨 앞을 적용하면, Then A가 히트 테스트와 시각에서 B 위에 있다.

##### P1-4. 스냅 / 가이드

드래그 중 다른 인스턴스 가장자리·중앙, 캔버스 중앙에 정렬 가이드. 스냅 거리 **가정** 4px. on/off 토글.

**수용 기준**: Given 스냅이 켜져 있고 A 가장자리에 B를 가져가면, When 가이드가 보이면, Then 놓았을 때 가장자리가 1px 오차 내로 맞는다.

##### P1-5. 리사이즈 핸들

선택 박스 코너/엣지 드래그로 `width, height` 변경. P0는 인스펙터 숫자만으로도 가능.

**수용 기준**: Given 선택이 있을 때, When 코너 핸들을 드래그하면, Then width/height가 변하고 하한 이하로 줄지 않는다.

##### P1-6. 베이스 목업 숨기기

오버레이만 보는 토글. 꺼도 인스턴스 좌표 유지.

**수용 기준**: Given 토글 off면, When 중앙을 보면, Then 베이스 목업은 안 보이고 인스턴스와 빈 캔버스 배경만 보인다.

##### P1-7. 임의 hex / 타이포 세밀 조절

역할 토큰 외에 hex, 폰트 크기. 키트 일관성 경고 가능.

#### 6.9 P2 — Could

- 컴포넌트 간 간단 링크(클릭 시 스크롤).  
- 이미지 파일 로컬 업로드(data URL, 용량 한도).  
- 인스턴스 복제.  
- 정렬 분배(좌/우/간격 균등).  
- 코드 패널에 “전체 캔버스” 번들 export (여전히 비실행).  
- 터치 디바이스 전용 제스처.

### 7. 비기능 요구사항

#### 7.1 성능

- 인스턴스 **50개**까지 드래그 중 프레임이 사용 가능해야 한다. **가정**: 목표 데스크톱 60fps는 최선, P0 게이트는 50개에서 입력 지연이 명백히 깨지지 않는 수준.  
- 속성 키 입력 p95는 생성 API와 무관, 로컬 즉시.  
- localStorage 기록은 디바운스 **가정** 300ms. 드래그 매 픽셀마다 동기 풀 직렬화 금지.

#### 7.2 보안

- `props`와 코드 패널 문자열을 DOM에 넣을 때 **실행 가능한 스크립트를 주입하지 않는다**. 텍스트는 텍스트 노드/이스케이프. `image.src`는 `http(s)` 또는 빈 placeholder만 **가정**. `javascript:` URL 거부.  
- 모델 API 키는 부모와 같이 브라우저에 두지 않는다. 본 기능은 추가 생성 호출을 **필수로 하지 않음**.

#### 7.3 접근성

- 팔레트 적용, 인스펙터 필드, 삭제는 키보드로 완료 가능.  
- 캔버스 드래그는 P0에서 마우스 우선. 방향키 1px/10px 이동은 P1.  
- 선택 상태는 링+“선택됨” 텍스트/aria.  
- 목표: 부모와 같이 핵심 플로 WCAG 2.2 AA에 근접.

#### 7.4 다국어

- UI 라벨·빈 상태·잠금 문구 **한국어**.  
- 인스턴스 `props` 문자열은 사용자 입력 그대로(한/영).

#### 7.5 브라우저

- 부모와 동일: 최신 Chrome, Safari, Firefox 데스크톱. IE 없음.  
- DnD·Pointer Events가 동작하는 환경. **가정**: 트랙패드 클릭-드래그 지원.

#### 7.6 감사 로그

- 1차 로컬 제품. 서버 감사 없음. 콘솔에 인스턴스 페이로드 전체 덤프를 기본으로 하지 않는다.

### 8. 성공 지표·실험

부모 북극성(완료 프로젝트 수)은 유지한다. 본 기능은 **프로토타입 스텝 내부**만 가볍게 본다. 1차는 계정이 없으므로 **가정**: 로컬/내부 알파에서는 세션 카운트·정성 리뷰, 상용화 때 이벤트로 이전.

#### 8.1 핵심 KPI 후보

**프로토타입 활성 세션 중 캔버스 사용률**: 프로토타입 스텝을 연 세션 가운데 인스턴스 추가 성공 ≥ 1회 비율.

#### 8.2 선행 지표

- 적용 클릭 또는 DnD 추가 1회까지의 시간(프로토타입 스텝 진입 후 중위).  
- 인스턴스 추가 후 드래그 이동 1회 비율(추가만 하고 안 옮기는 비율과 비교).

#### 8.3 후행 지표

- 새로고침 후 동일 프로젝트에서 인스턴스 수 불일치 보고(버그 프록시).  
- 캔버스 비우기 사용 비율(오염·실수 프록시).

#### 8.4 가드레일

| 가드레일 | 임계(가정) | 대응 |
| --- | --- | --- |
| 편집 잠금인데 트리가 삭제됨 | 발생 0 | stale 정책 회귀 테스트 |
| 코드 패널/URL로 스크립트 실행 | 발생 0 | src 화이트리스트, 텍스트 이스케이프 |
| DnD 추가 실패(활성 상태인데 0 생성) | 내부 알파에서 재현 시 | 히트 영역·게이트 점검 |

#### 8.5 실험

MVP는 단일 플로. A/B 없음. DnD 드롭 좌표 vs 중앙은 오픈 이슈 1을 알파에서 5명 과제로 관찰 후 고정.

### 11. 오픈 이슈·결정 로그

#### 11.1 미정 사항

1. **DnD 최초 좌표**: 드롭 지점 중심(현 가정) vs 항상 캔버스 정중앙(원문 충실).  
2. **코드 패널 언어**: JSX vs 순수 HTML vs 둘 탭.  
3. **베이스 목업 P0 필수 표시 여부**: 항상 배경 vs 빈 캔버스 시작(확정 키트만 사용). 현 가정은 항상 배경.  
4. **논리 캔버스 크기**: 프레임 CSS 픽셀 vs 고정 1440×900 논리 후 스케일.  
5. **삭제 확인 모달** 여부. 현 가정은 P0 즉시 삭제.  
6. **인스턴스 상한**: 50 경고 vs 하드 캡.  
7. **navigation/tabs**의 항목 수를 인스펙터에서 늘릴 최대값. 현 가정 내비 5, 탭 4.  
8. 구 프로젝트 persist 마이그레이션 실패 시: 빈 배열로 복구 vs 프로젝트 로드 실패 안내.
